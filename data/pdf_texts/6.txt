命令式 API：四個零件組一個 tool 🔩
await document.modelContext.registerTool({
  name: 'add_to_cart',
  description: '把商品加入購物車，需要商品 ID 與數量',
  inputSchema: {
    type: 'object',
    properties: {
      productId: { type: 'string', description: '商品 ID' },
      quantity: { type: 'integer', minimum: 1 }
    }, required: ['productId']
  }, 
annotations: { readOnlyHint: false }, // 選填
  execute: async ({ productId, quantity = 1 }) => { 
await cart.add(productId, quantity); 
return `已加入 ${quantity} 件`;
  } 
});
name
動詞開頭，一看就懂
description
什麼時候該用它
inputSchema
標準 JSON Schema
execute
真正做事，把結果回給 AI
annotations（選填）
給 agent 看的警告標籤

=== Page 15 ===
Annotations：幫 tool 貼上警告標籤 🏷️
📖
readOnlyHint
只讀不寫，放心呼叫：查庫存、查訂單狀態。
💣
consequentialHint
真實、不可逆的後果：付款、刪資料 → 瀏覽器可以強制
跳確認。
🧪
untrustedContentHint
回傳含使用者產生的內容（評論、留言）→ 提醒 agent
防 prompt injection。
🔧
debugging
給 DevTools 與測試用，一般 agent 可以過濾掉
（Chrome 156 起）。

=== Page 25 ===
安全：每個 tool 都是新的攻擊面 🛡️
🧪Prompt Injection
評論、留言可能夾帶指令 → untrustedContentHint，資料與指令分開
💳高風險動作
consequentialHint ＋ 人類確認；付款表單不要 toolautosubmit
🪟跨來源 iframe
預設禁止註冊；要 allow="tools"，再明確授權來源
🔐execute 裡再驗一次
AI 給的參數跟使用者輸入一樣不可信；權限不能只靠 UI 藏按鈕
