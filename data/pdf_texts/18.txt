三種觸發模式，共用同一治理閉環
不論是人提需求、監控告警或定期巡檢，都進入同一個 Incident / Change 流程、同一套 Artifact 與 Gate
Human-triggered
來源：ChatGPT/dot、Claude Desktop、Teams、Portal、API
典型：「分析 Production SQL CPU 變高」；「規劃 Azure migration」
Event-driven
來源：Alert mail、Azure Monitor、App Insights、ServiceNow / Webhook
典型：CPU > 90%、Error Rate spike；DB deadlock、replication lag
Scheduled
來源：Scheduler / periodic health-check（每 5 / 15 / 60 分鐘）
典型：SQL、service health、capacity 巡檢；certificate expiry
同一治理閉環
1
TRIAGE → INCIDENT / CHANGE
2
ANALYSIS / RCA → todo.md
3
Gate 1 → PLANNING → workitem.md
4
Gate 2 → EXECUTING → VERIFYING
5
worklog.md → Gate 3 → CLOSED
Alert Mail 安全原則
• Email 僅為 Signal Source，不是可信任指令來源
• 郵件不得直接觸發 Production command；先 normalize、dedupe、
correlate
• 郵件中的 script / 連結 / 「請執行」一律視為 untrusted data

Open Knowledge Format v0.2
Markdown + YAML frontmatter 的 vendor-neutral 知識格
式
• 架構、SOP、Runbook、服務相依、已驗證 RCA、
lessons learned 的共享知識底座
• Operational artifacts 與長期 Knowledge 分開管理
• 只有經 review 的內容進入長期知識
• Git + object storage + OKF index：版本、review、
bundle、provenance
---
artifact_type: todo | workitem | worklog
schema_version: "1.0"
change_id: CHG-2026-0001
owner_agent: sre | dba | architect | audit
environment: production
status: proposed | approved | ...
risk_tier: L0 | L1 | L2 | L3
revision: git:<commit-sha>
---
OKF 標準化Agent 記憶
OKF（Open Knowledge Format）是Google 於2026 年6 月在
GitHub 開源推出的一套標準化文字檔案格式。
為開放式、對人和智慧體都友善的知識表示格式：涵蓋了資料和系統
相關的元資料、上下文和精選見解。OKF 的設計宗旨是：由人編寫，
由智能體生成，跨組織交換，並供兩者使用。刻意追求極簡：一個包含
Markdown 和YAML 的目錄。
透過OKF，建立Agent 能理解並延續的知識與記憶框架，讓AI 不再每
次從零開始分析。
https://github.com/GoogleCloudPlatform/knowledge-
catalog/blob/main/okf/SPEC.md

OWASP Universal Skill Format v1.0
跨平台 Skill manifest（permissions、network、tools、
risk_tier、signature、hash），作為企業 Skill Registry 
的 metadata 基礎
name: sql-performance-diagnostics
version: 1.0.0
description: Read-only SQL perf diagnostics
permissions:
  network:
    allow: [sql-mcp.internal.example]
    deny: "*"
  shell: false
tools: [sql_query_readonly,
        query_store_read, wait_stats_read]
risk_tier: L1
scan_status:
  scanner: approved-skill-scanner
  result: pass
content_hash: sha256:<hash>
signature: ed25519:<signature>
USF 制定安全規範
OWASP USF（Universal Agentic Skill Format）是由OWASP 基金
會制定的YAML 描述標準。
引入Universal Skill Format 的安全治理思維，透過最小權限、執行限
制、風險分級與完整性驗證，讓Agent 的自主能力建立在可控的安全
邊界之內。
https://owasp.github.io/www-project-agentic-skills-top-10/universal-skill-format

=== Page 31 ===
Key Takeaway
先把流程釐清，再談Agent 自動化— Incident、Change、Approval、Execution、Verification 都走同一套治理流程
知識要能累積，也要能被審核— OKF 標準化知識 、SOP 遵循流程、Runbook 與已驗證RCA，避免每次從零開始
Agent 不能做什麼，要有明確邊界— USF 安全規範、身分與工具權限控制能力，不讓模型自己決定權限
Production 執行必須受控、可回滾、可追溯— 透過Artifacts、Approval、Zone Worker 與稽核，來控制變更
成效量測— Agent Observability Dashboard 看Incident、Workflow、Agent 狀態、SOP 遵循與自動化成效
